# Documents Premium Pass — batch153 (2026-10-23)

Owner's order: every PDF download and every download in the app must be
PREMIUM — one design language for every document the school hands out —
plus two additions: (1) every document must UTILIZE THE PAGE properly
(no mostly-empty pages, no wasted margins); (2) DYNAMIC BRANDING IS A
HARD RULE — logo / school name / signature / seal are pulled from
Settings at generation time, never hardcoded or bundled.

Circulars are excluded (owned by the circular squad).

## Root cause found for most defects

This install's dompdf has remote image fetching DISABLED. Any document
blade that feeds dompdf the Settings logo as a URL renders a
broken-image "X" placeholder (header logo AND watermark). The codebase
already had the cure in two places (MarkController::pdfImageDataUri,
CircularController, App\Support\ExamDateSheet) — inline the stored
file as a base64 data URI on the PDF path only. This pass applied
that established pattern everywhere it was missing; browser-print
twins keep the URL untouched (verified: the receipt screen page still
serves `src="…/storage/uploads/logo.svg"`, and the register's browser
print page still shows its Print bar).

## Owner addition 1 — page utilization

Checked per document above (page count + text coverage). Fixes made
where utilization failed: receipt 2→1 pages, register PDF 2→1 pages,
admit sheet 5→4 pages with pairs sharing pages and the blank page
eliminated, invoice print changed from a screen dump to a real
one-page statement. Documents left alone were already at one page
with professional fill for their data volume (e.g. the annual card's
57% vertical is two-subject nursery data, not wasted space).

## Owner addition 2 — dynamic branding (HARD RULE)

Every document above resolves its branding from Settings AT
GENERATION TIME: school name via `Qs::getSystemName()` /
`settings.system_name`, logo via `Qs::getSetting('logo')`,
signature/stamp via the settings values the controllers already
inline for report cards, admit cards and the date sheet. The hunt
for hardcoded/bundled branding found NO document template with a
baked-in school name or bundled logo image; the defects were all
the same mechanism — the Settings logo fed to dompdf as a URL it
cannot fetch. ("Generated by Hackstra" footers are the platform
credit line, not school branding.)

PROOF: on the test server the `logo` setting was swapped to an
unmistakable test image (magenta square, yellow star,
`storage/uploads/test-logo.png`) and the fee receipt PDF was
re-rendered WITHOUT any code change — the receipt header carried
the star logo. The setting was then restored to the seeded logo and
the receipt re-rendered with the original H logo. Both renders were
visually inspected.
